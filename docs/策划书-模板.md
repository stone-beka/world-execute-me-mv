# world.execute(me); MV 策划书 —— 参考模板

> **这是格式，不是内容。** 里面的「示例」是拿一个跟这首歌无关的题材瞎编的，
> 只用来说明**颗粒度**，看完就扔，别照抄。
>
> 用法：复制本文件到 `docs/策划书.md`，从第一节开始填。
> **不用一次写完全片。** 写清楚一段，我们就能开工一段。

---

## 0. 一句话立意

用一句人话说清楚：**这个 MV 到底在讲什么？**

不一定要有"故事"。但要有**一个能贯穿全片的动机**，否则每个画面各玩各的，拼起来是合集不是作品。

```
示例：
「一个进程在反复尝试描述自己，但每次描述的词语都会在下一次循环里被覆盖，
  画面越靠近结尾，同一块区域被覆写的痕迹越明显。」
```

## 1. 视觉基调

只要写你**真的要**什么，不用写不要什么（不要的写在第 6 节）。

| 项 | 填什么 | 示例 |
|---|---|---|
| 画面质感 | 像什么？ | 「老式 CRT 终端 / 单色绿字 / 有扫描线和微弱抖动」 |
| 主色 | 2~3 个 | 「黑底、磷光绿、偶发琥珀色警告」 |
| 参考 | 你说得出来就行 | 「《攻壳》的文字叠层」「ae 里那种故障字」 |
| 明暗节奏 | 全片是越来越暗还是越来越亮？ | 「副歌爆白，主歌压暗」 |

**参考可以很粗糙。**「像那个……就是那个很酷的加载界面」也行，我读不懂会问你。

## 2. 时间基准（已定，直接抄）

这些已经量好了，**你写策划时直接引用就行，不用管**：

| 参数 | 值 |
|---|---|
| BPM | 130.000 |
| 一拍 | 461.52ms |
| 一小节 | 4 拍 = 1846.08ms |
| 第 1 拍 | 音频第 **459.7ms** |
| 全片长度 | 212.000s（3:32） |
| 分辨率 / 帧率 | 1920×1080 @ 60fps |

> 换算小抄：**第 N 拍 = 459.7 + (N−1) × 461.52 ms**
> 所以「第 33 拍」≈ 15.24 秒。

**写时间建议用「拍/小节」而不是「秒」**，因为你的画面是踩在拍上的：
「第 17 小节第 3 拍」比「31.3 秒」精确，而且我改不坏。
秒也行，我会自己换。

## 3. 段落表（全片骨架）

**先只写这一节，我们就能开工。** 把全片切成几段，每段写清楚：时间 + 情绪 + 发生什么。

| 段落 | 起止（拍或秒） | 情绪/功能 | 一句话说发生什么 |
|---|---|---|---|
| INTRO | 第 1 拍 ~ 第 32 拍 | 空白、待机 | 屏幕从无到有，像机器刚通电 |
| … | … | … | … |
| OUTRO | – | 收束 | – |

写不了精确时间没关系，写「大概前半段」我也能用。

## 4. 关键画面清单 ★ 核心

**一节 = 一块画板 = 一个时间段。** 这是我们一次做一个的单位。

每块照下面填。**能填几项填几项，填不了留空，我会问你。**

```markdown
### SHOT-03  名字（随便起，用来指代）
- **时间**：第 65 拍 ~ 第 96 拍    （或者：第 2 个副歌开始 ~ 副歌结束）
- **画什么**：具体到能画出来的程度
- **怎么动**：
    · 整体：随时间/随拍，怎么变？
    · 卡拍：每一拍发生什么？（有没有"咚"一下）
    · 细节：有没有不该规律的抖动、漂移？
- **怎么进出**：淡入？淡出？硬切？还是"被下一个画面推开"？
- **歌词对应**：这几秒在唱哪句？（没有就写"无"）
- **依赖**：需要先有别的画面吗？（比如"要接着 SHOT-02 的位置"）
- **不要什么**：我不想要的效果（这一条很有用，能挡掉我加戏）
```

### 填得好的例子（题材无关，只看颗粒度）

> ### SHOT-07  传输进度
> - **时间**：第 129 拍 ~ 第 160 拍
> - **画什么**：画面正中一条水平细线，从左向右被填满。线下方一串等宽数字，
>   被填到的地方数字变亮，没填到的地方是暗灰。
> - **怎么动**：
>   - 整体：填满速度不是匀速，是大致跟拍——每拍往前跳一小段，跳的幅度每拍略不同
>   - 卡拍：每拍线短暂亮一下（大概 1/10 拍就衰减掉）
>   - 细节：数字有轻微上下抖动，不是整齐的
> - **怎么进出**：从上一块的位置直接长出来，不退场；在 SHOT-08 开始时被覆盖
> - **歌词对应**：无
> - **依赖**：SHOT-02 的坐标系（线的高度要对齐）
> - **不要什么**：不要百分比数字，不要"完成"字样

### 填得差的例子（对比着看）

> ### 某个画面
> - 时间：中间那段
> - 内容：很酷的科技感，有点故障艺术的感觉，要燃
> - 动效：动起来就行

**差在哪**：没有时间、没有具体图像、全是形容词。
「很酷」「燃」「科技感」我无法实现——我只能猜，而猜错就是浪费你一轮。

## 5. 全局规则（贯穿全片的东西）

这些写一次，全片生效，不用每块重复。

```
示例：
- 转场：除了标了「硬切」的，一律 100ms 淡入淡出
- 抖动：全片始终有一层极轻微的扫描线在缓慢下移（速度跟拍，不是跟秒）
- 配色：琥珀色只在"出错/警告"时出现，其他时候一律绿色系
- 文字：一律等宽字体，字号只有 3 档
```

---

## 6. 明确不要的

写清楚你不要什么，比写你要什么更省事。

```
示例：
- 不要真人画面、不要照片拼贴
- 不要镜头运动（推拉摇），画面永远是"平的"
- 不要出现具象的角色形象
- 不要花哨的粒子爆炸
```

---

## 7. 待定 / 我还没想好的

**这一节可以尽管写。** 你写「这里我也不知道要什么，感觉应该有东西」，
我就知道这块要跟你一起想，而不是自己编一个。

```
示例：
- 第 3 段（大概 1:20 左右）我不知道放什么，但这段不能空着
- 结尾想要"被删除"的感觉，具体怎么表现还没想好
```

## 8. 开工前自检（写完花 30 秒过一遍）

对着每个 SHOT 问 5 个问题：

1. **有时间吗？** 拍号、秒数、或者"某个副歌"都行——但得有。
2. **能画出来吗？** 是"屏幕上的图形/文字"吗？
   注意：本引擎是 **Canvas 2D 画图形**，不是实时 3D，也不是剪辑真人素材。
   点、线、圆、多边形、文字、渐变、噪点、扫描线、发光、故障、波形——全都没问题。
   如果你想要的是"真实人物在跳舞"，那得换方案，我们得先聊。
3. **靠什么动？** 跟时间流、跟拍、还是被某个事件触发？
4. **怎么接上一块？** 是"变过去"还是"切过去"？
5. **有没有整块只是一个形容词？**（"很燃""很有科技感"）→ 中一条就补一张具体画面。

## 附：本引擎的边界（免得白写）

**能做到**
- 任何 2D 图形、文字排版、渐变、噪声、扫描线、CRT 感、发光、故障位移
- 逐帧精确控制，卡拍可以精确到 1/60 秒
- 叠加：多块画板同时存在，可以互相压
- 导入静态图片当素材（PNG/JPG）

**要额外动管道，但能做**
- 把视频当素材：需要先用 ffmpeg 抽成帧序列，成本高，尽量少用

**做不到 / 很贵**
- 实时 3D 场景、真实物理模拟
- 依赖系统字体（跨机器会变）——要特殊字体得把字体文件放进项目
- 任何"实时"的东西：这是**离线逐帧渲染**，没有交互
