## 二、最重要的设计决定：**元素登记改成「运行时」，不再扫源码**

### 为什么（这是这轮的核心）

原来 `tools/elements.js` 用**正则扫源码**找元素，只认「写死数字坐标」的调用。结果：

- 循环里画的棋子（`chessPiece(ctx, x, y, ...)`，x/y 是变量）→ **完全漏掉**
- 算出来的坐标、双层循环的盾牌水印、碎片、摄像头取景框 → **全部漏掉**

**静态扫描永远追不上「运行时才决定的坐标」。**

### 现在的做法

装置在**真正画的时候**自己报名（`src/boards/_ui.js` 顶部的 `reg()`）：

```js
function reg(s, device, x, y, w, h, text) {
  if (!s || !s.__reg) return;   // 正常渲染时 __reg 不存在 → 零开销
  s.__reg.push({ board: s.__boardFile, device, x, y, w, h, text });
}
```

- 检查器渲染时注入 `s.__reg = []`（见 `src/core/render.js` 的 `opt.reg`）
- 正常出片路径**完全不传**，所以零开销、不影响确定性（四关已验证）
- 24 个可见装置都插了一行 `reg(...)`

### ⚠️ 踩过的坑（**下一个 AI 务必看**）

**自动插入 `reg()` 时插到了变量声明之前 → 运行时崩溃 `Cannot access 'x' before initialization`。**

受害的 9 个：`panel` `dialog` `trashDone` `radio` `checkbox` `select` `typewriter` `feelingIndex` `chip`
（它们都是 `const { ... } = opt` 解构之后才用到那些变量，而 `reg()` 被插到了解构之前）

**规矩：`reg()` 必须放在函数体里所有它用到的变量都声明之后。**
排查脚本（临时写的，已删，可重建）：找每个函数的 `reg(s,` 行，看它用到的变量是否在该行之后才 `const/let`。

**另一个坑**：`chessPiece` 原签名是 `(ctx, cx, cy, hgt, ...)`，**没有 `s` 参数**。
加 `reg()` 时必须同时改签名 + 改所有调用点（`01-boot.js` 和 `02-title.js`）。
这个漏改过一次，导致棋子仍然登记不到 —— 如果你发现「某个装置怎么都不登记」，**先查它有没有 `s` 参数**。

3. 新工具里的 `Date.now()` 会被 `verify:determinism` 的静态扫描抓到 —— 工具类要按
   `tools/lib/progress.js` 的先例进 `verify/determinism-check.js` 的 **ALLOW 表**（并写清「不进画面」）。

## 六、这一轮的教训（写给下一个 AI）

1. **别用脚本批量改源码然后不复检。** 我用脚本给 24 个函数插 `reg()`，插错位置产生 9 个 TDZ 崩溃，来回修了四五轮。**批量改完必须逐个跑一遍静态检查。**

2. **`edit` 工具偶尔会静默失败。** 这轮出现好几次：我调用 `edit`，返回成功，但**文件没变**（`trashDone`、`01-boot.js:136` 都遇到过）。**改完一定要用 grep/read 复读一遍确认。**

3. **复检不通过时，先看文件，别再跑脚本。** 我连续跑了好几轮「修 → 复检 → 还错 → 再修」的循环，实际上第一次复检不过时就该直接打开文件看。

4. **工具会断连。** 这个会话里出现过 `ECONNRESET`、`browser.evaluate timeout`，还有写文件「写了三次都不在磁盘上」。**断了就接着做，但每次续上先复核状态**，不要假设上次那步成功了。

5. **一次别推太多。** 用户给的链条很长（图层→右键→运行时登记→修 bug），我一路往前冲，导致中间状态很乱。**每个小节点停下来确认。**
